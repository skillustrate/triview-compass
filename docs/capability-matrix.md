# V1 adapter capabilities and data flow

Reviewed content is inert input to trusted adapters. A capability document is an assertion about the host implementation; prompts and returned context IDs do not independently prove enforcement. Unsupported required controls refuse the affected mode.

| Adapter | Supported profile | Enforced by implementation/host | Assumptions and limits |
| --- | --- | --- | --- |
| Static harness | Frozen supplied-file or committed Git evidence | No reviewer tools; immutable sanitized snapshot; pinned policy/scope; no reviewer writes, execution, or network access | Application installation and `.git` configuration are trusted; source and role definitions must come from separate trust domains |
| Claude Code subscription | CLI **2.1.300**, first-party `claude.ai` subscription auth; one account or explicit role profiles | Version/auth checked before source preparation; fresh print processes; safe/restricted modes; empty tools; strict MCP; no persistence; clean environment; bounded preflight and forced cancellation; evidence IDs/line bounds/skills constrained in output schema | Managed host policy still applies. Model alias, context capacity, and 65,536-token wrapper reserve are configured assumptions. Observed served model names and numeric usage can be recorded after calls; no exact pre-request tokenizer exists. No `--bare` mode because it excludes subscription auth |
| LM Studio local | Programmatic experimental adapter; trusted localhost or literal private-network HTTP(S) endpoint | No HTTP redirects; bounded metadata fetch; loaded GGUF/MLX identity; SDK tokenizer; stateless requests; no tools; structured response; response identity and usage bounds | Private address does not prove processing locality; the server may proxy or retain data. Tokenizer margin is empirical, not a proof for all server versions. SDK operations must honor host cancellation; core stops dispatch on preflight expiry. Live quality is not a release gate per the user's direction |
| Podman sandbox | Linux, local rootless engine, seccomp, cgroups v2; already-local digest-pinned image | Read-only sanitized captured files/root; non-root user; no network/proxy forwarding; no image-defined volumes; bounded CPU/memory/processes/scratch/output/time; scanned output; no host fallback or image pull | Trusted patched engine, host configuration/hooks, and image are required. Containers share the kernel. Only included sanitized non-deleted files are assembled, not a full checkout |
| Antigravity or other subscription CLI | **Unsupported** until a trusted adapter implements the contract | Unsupported route configuration is refused; core accepts separately supplied reviewed adapters | Tool-free isolation and memory controls must be verified before declaring support. A second subscription is optional |

## Data flow

1. The caller chooses a complete policy, provider route(s), captured input, optional sandbox command/image, and optional audit retention. Reviewed text cannot choose those settings.
2. Core captures committed Git objects or supplied files, filters paths, scans known secret patterns, freezes evidence, and constructs prompts with opaque file IDs and explicit one-based source lines. Included Git files also carry numeric base/target hunk coordinates; raw patch text and headers are never sent; deleted-file evidence still shows the captured base file. Redacted files withhold change coordinates because sanitization may shift line numbers. Missing partial-clone objects refuse capture without lazy fetching.
3. Trusted runtime/auth/tokenizer operations prepare exact serialized requests under a shared preflight deadline. A source-free capability report exposes handling, controls, bounds, coverage, prompt versions, and limitations. Known secret patterns in capability metadata are withheld.
4. Approved hosted review sends sanitized evidence and static reviewer guidance to the selected subscription provider via stdin. Three separate processes receive independent contexts. Local review sends equivalent bounded evidence to the trusted local server. No reviewer gets another reviewer's output.
5. Core validates schemas, identity, known-secret output, evidence IDs, line bounds, and verdict consistency, then retains disagreements and structurally unverifiable findings. Valid ranges do not prove semantic relevance; numbered lines and change context guide model judgment but do not enforce it. A failed role makes the report incomplete.
6. Optional execution uses the same sanitized captured files in the validated sandbox. Output is scanned and stays outside reviewer prompts. Requested failed/skipped execution produces an incomplete report.
7. The default result is a report. Optional audit persistence stores metadata/hashes as private files, with explicit retention. Evaluation artifacts also default to scores, identity hashes, latency, and numeric metrics rather than prompts or transcripts.

CLI capability evidence comes from the installed `claude --help`, live subscription checks, and [official CLI documentation](https://code.claude.com/docs/en/cli-reference). Git's [documented no-lazy-fetch control](https://git-scm.com/docs/git/2.53.0.html) closes implicit partial-clone fetching. See [security review](security-review.md) for tested controls and residual risks.
