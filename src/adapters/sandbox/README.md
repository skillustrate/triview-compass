# Sandbox adapter implementations

`podman-preflight.js` checks the `linux-rootless-podman-v1` profile. It requires explicit execution opt-in, Linux, a fully qualified image reference pinned by SHA-256 digest, a local rootless Podman engine with seccomp and cgroups v2, and a matching image already present locally. It does not pull images or read source. Failure returns a sanitized `skipped` result.

`podman-runner.js` is an opt-in execution adapter used by the review workflow and CLI. The caller supplies a validated policy, frozen sanitized bundle, pinned image, and explicit command array. It materializes only included, sanitized, non-deleted files in a private temporary directory; this is **not a complete repository checkout**. It mounts those files read-only, gives the container a separate bounded scratch tmpfs, uses a non-root user, disables networking and proxy forwarding, bounds CPU/memory/processes/time/output, and scans output before returning it. Image-defined volumes are ignored. It never runs the command on the host or pulls an image. Failure reasons omit raw Podman errors.

The synthetic probe `node evals/scripts/probe-sandbox-runner.js <local-image@sha256:...>` checks the effective UID, read-only source, scratch write access, network interfaces, and cgroup limits inside an already-local pinned Python image. It never uses repository source. A `ready` preflight result alone does not authorize execution; the explicit command and runner controls are also required.

`probe-sandbox-workflow.js` uses diagnostic reviewers with no provider calls and a real Podman container to exercise CLI disclosure, captured project-schema verification, report/audit integration, timeout, output redaction, and a missing image. The workflow exposes scanned output in the report and keeps audit data to status and identity hashes. A failed or skipped requested check makes the report incomplete. See [CLI usage](../../cli/README.md) for configuration and supported runtime guidance.
