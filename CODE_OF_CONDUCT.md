# Code of Conduct

## The standard

Be respectful and assume good faith in issues, pull requests, and any other project space. Disagreement about design, code, or priorities is normal and welcome — personal attacks, harassment, discriminatory language or behavior, and deliberately bad-faith engagement are not.

Concretely, this means:

- Critique the code, the proposal, or the argument — not the person who wrote it.
- Assume a mistake is a mistake, not malice, until shown otherwise.
- No harassment, insults, discriminatory jokes or language, unwelcome personal attention, or doxxing.
- Respect that the maintainer bandwidth described in `CONTRIBUTING.md` is real; disagreement about priorities is fine, demanding a response is not.

## Reporting

Report a violation privately through the same channel `SECURITY.md` describes for security issues — this project doesn't yet have separate conduct-reporting infrastructure, and that channel reaches the maintainer directly without requiring a published email address.

## Enforcement

As a single-maintainer project, enforcement is the maintainer's judgment call: a warning for a first, minor issue; a temporary or permanent ban from project spaces for anything more serious or repeated. There is no appeals committee at this project's current size — if that changes as the project grows, this document will be updated to say so.
